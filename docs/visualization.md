# 可視化 ── このアプリの核心

「これまで自分が何をしてきたかをグラフィカルに見る」が目的。
苔のメタファー（[concept.md](concept.md)）を視覚に落とし込む。

## 1. 総草ヒートマップ（＝ GitHub の草、ただし苔）

最優先で作る可視化。**ヒートマップはこの 1 枚だけ**（2026-09-02 決定）。

- 横軸：日付（週ごとの格子）、縦軸：曜日。GitHub の contribution graph と同形式。
- マスの濃淡＝**その日に在った全苔片の数（タグ無しも含む）**。見たいのは「その日どれだけ積まれたか」という活動量。
  軸は「日」の範囲（2026-09-06、[ADR-0005](adr/0005-post-axis-is-day-range.md)。軸そのものは ✅ 同日 merge #43 — 読む側は `first_day` / `last_day`
  の重なりで数える。過去の日に積む・続く苔片を**作る**側も ✅ 同日 #47 — ダイアログの「積む日」、[features.md](features.md) §1）:
  過去の日に積んだ苔片はその日に、**続く苔片**（[CONTEXT.md](../CONTEXT.md)）は最初の日〜最後の日の各日に +1
  （固定の 5 段階に乗る。厚み（[ADR-0007](adr/0007-spanning-post-amount-is-days-times-thickness.md)）があっても各日 +1 —— 総草は在ったことを見せる場所で、量は読まない）。「計 N 片」は窓に**重なる苔片の数**で、マスの合計ではない（絨毯で水増ししない）。
- **色相は「向き」で変わる**（濃さは件数のまま。決定 2026-09-06、✅ 同日 #46、plans の B）: 日ごとに 入（インプット＋両方）と
  出（アウトプット＋両方）を数え、入 > 出 は**吸う色（水を含んだ苔の青緑）**、出 > 入 は**出す色（胞子体の赤茶）**、
  同数・未分類だけ・0 件は苔の緑。1 マス 11px なので優劣の 3 色相で足りる（比で連続的に混ぜる案は退けた）。
  配色は OKLCH で `--moss-*` と段ごとに同じ明度（濃さ ＝ 件数 を色相をまたいで保つ）、色相は青緑 h 225・赤茶 h 55 —
  `dataviz` の validate_palette で候補を総当たりして moss との分離が最大の組を固定した（`styles.css` に実測値）。
  同じ明度に縛るので色相だけの分離は categorical の門に届かない（deutan で赤茶↔緑 ΔE 5.8〜7.6）。だから向きは
  言葉でも運ぶ: 凡例は「少〜多」の 1 列に 2 色を添え、マスの読み上げとツールチップは
  「YYYY/MM/DD · N 件（インプット a・アウトプット b）」（向きのある日だけ内訳が付く）、キャプションに窓ぜんたいの比率
  「吸う x% · 出す y%」（分母は窓に重なる全苔片。両方 は両側に数えるので和は 100 にならず、未分類が多ければ届かない。
  向きのある苔片が 1 つも無い窓には出さない）、カードには向きの印（言葉 ＋ 色相の点）。
- **タグ別のヒートマップは作らない。** タグへの打ち込みは別の形で見る —
  「どれだけ」は [§6 タグ関係グラフ](#6-タグ関係グラフ共起ネットワーク)のノードの育ち、
  「どれだけの期間」は [§8 タグのタイムライン](#8-タグのタイムライン打ち込み期間)。
- マスにホバーでツールチップ（M/D · N 件）、タップでその日の投稿一覧へ — ✅ 2026-09-05。着地点は投稿一覧の期間絞り込み
  `?from=&to=` の 1 日形（「今日」プリセットと同じ窓）で、チップ「YYYY/MM/DD ×」で解除、石の絞り込みとは AND。
  マスは石（§6）と同じ role=button + Enter/Space 契約。Tab の停止は今日のマス 1 つで、矢印キー（↑↓ = 日、←→ = 週、
  Home/End = 窓の両端）で歩く — 53 週分のマスを全部 Tab 停止にはしない。

## 2. 累積グラフ（積み上げ）

「積み上げ」という要望の直接的な表現。

- タグ別の累積投稿数を **積み上げ面グラフ** で時系列表示。
- 全体が時間とともに分厚くなっていく ＝ 苔が堆積していく様子。
- 期間切り替え（月 / 年 / 全期間）。
- 量で積む（2026-09-09、[ADR-0007](adr/0007-spanning-post-amount-is-days-times-thickness.md)）: 続く苔片は在った各日に厚みずつ、単日はその日に 1。
- タグの表示 ON/OFF で見たい領域だけ重ねられる。

## 3. 苔の庭ビュー（メタファー直球の象徴的ビュー）

数値グラフとは別の、情緒的・象徴的な一覧。

- 各タグを「石」または「区画」として配置。
- 投稿量・継続度に応じて **苔の生え具合** が変化する（薄い苔 → びっしり繁茂）。
- 最近投稿のあるタグは瑞々しく、長く放置されたタグは乾いた表現に。
- SVG / Canvas で手描き。アプリの世界観を一目で伝える「顔」になる画面。
- パッと見て「今どの分野が育っているか / 枯れかけか」が直感で分かる。

## 4. ストリーク・継続指標

- タグ別の連続投稿日数（現在のストリーク / 最長ストリーク）。
- 「最後に書いてから N 日」。枯れかけタグへのそっとしたリマインド（通知ではなく表示のみ）。
- 月間アクティブ日数（その月に何日書いたか）。

## 5. 内訳・分布

- タグ別投稿数の割合（円 / 棒）。期間で切り替え。
- 向き（インプット／アウトプット）の偏り。最初の形は総草のキャプションの比率（§1）。
- 時間帯ヒストグラム（自分が何時に書きがちか）。
- 曜日別の傾向。
- タグの共起（同時に付けられやすいタグの組み合わせ）→ 一覧表ではなくグラフとして見せる（[§6](#6-タグ関係グラフ共起ネットワーク)）。

## 6. タグ関係グラフ（共起ネットワーク）

「自分の関心領域がどう繋がっているか」と「各タグにどれだけ打ち込んだか」を見る。
石（タグ）同士を苔が橋渡ししているイメージ。

- ノード＝タグ（**大きさ＝投稿数。投稿が増えるほど石がどんどん育ち、打ち込んだ量が一目でわかる** —
  タグ別ヒートマップの代わりはこれ）、色＝タグの色。エッジ＝同じ投稿に一緒に付いた回数（太さ＝共起回数）。
- **大きさも太さも「量」**（2026-09-09 決定、[ADR-0007](adr/0007-spanning-post-amount-is-days-times-thickness.md)、✅ 2026-09-12 集計 — [plans/thickness.md](plans/thickness.md) PR 2）:
  続く苔片は 日数 × 厚み で石を育て橋を太らせ、単日は 1。期間で絞れば重なった日の分だけ（クリップ: 今月 / 今年 は 初日〜今日 の窓、全期間は窓なし）。
  wire は `count` → `amount`（小数のまま。丸めるのは表示だけ）、石と橋の名前・ツールチップは「量 N」（`Math.round`、1 未満は 1 桁）。
  ノードの目盛り（`nodeRadius`、量 ≈ 46 で上限）は据え置き — 量で早く飽和するので、実物を見てから決める。
- 期間で絞れる（今月 / 今年 / 全期間。重なりで引くので、去年始まって今年まで続く苔片は「今年」に入る — ADR-0005）。時間とともに橋が太くなる・新しい橋が架かるのを眺める。
- **グラフは両方の見かた（投稿一覧 / 年表）の操作盤**（2026-09-07、[features.md](features.md) §3）: ノードをタップで **選んだ石**
  （[CONTEXT.md](../CONTEXT.md)）に足し引き、エッジをタップで両端をまとめて足し引き。選んだ石は投稿一覧では AND の絞り込み、年表では
  軸（[§8](#8-タグのタイムライン打ち込み期間) の内訳）になる — 着地は見かたで変わり、状態は 1 つ。選ばれた石と両端が選ばれた橋は
  押された姿（`aria-pressed`）、残りは退く。（2026-09-03〜06 は ノード → §8 フォーカス、エッジ → 両タグの投稿一覧 の固定の着地だった。）
- 本文は使わない（`post_tags` だけ）。暗号化と両立（[data-model.md](data-model.md) の共起クエリ）。
- 実装は自作 SVG。タグ数十〜百程度なら力学レイアウトも自前の単純な反復で足りる。増えたら共起回数の下限でエッジを間引く。
- タグ運用の判断材料にもなる: 常に一緒に付いている 2 タグは統合候補、孤立したタグはアーカイブ候補（[features.md](features.md) §2）。

## 7. 振り返りダッシュボード

上記を組み合わせた「振り返り」ページ。

- 週次 / 月次 / 年次サマリー（投稿数、伸びたタグ、新しく生えたタグ）。
- 「今年の苔むす」── 年間まとめ（Spotify Wrapped 的な自分向け年次レビュー）。

## 8. タグのタイムライン（打ち込み期間）

「そのタグにどれくらいの**期間**打ち込んだか」を見る。§6 の「どれだけ（量）」と対になる「どれだけ（長さ）」。
仕事の苔片を積んでおけば**非公式スキルシート**（案件の従事期間・案件内で使った技術の期間）として読める
（2026-09-03 決定。案件もタグで表す — [features.md](features.md) §2。見出しは持たない — [ADR-0006](adr/0006-no-post-title.md)）。

- 行の一般形は「**タグ集合が全部付いた苔片** の最初の日〜最後の日」の横棒 1 本（単棒）＋ 件数。
  タグ 1 つなら従来どおりその石の行、複数なら組み合わせの行
  （例: `XX案件 × Vue.js × Hono` ＝ そのスタックで組んでいた内部プロジェクトの期間）。
- 既定表示は全タグ 1 行ずつ。並び順は開始日（年表として読める）。
- **フォーカス ＝ 軸は選んだ石の集合**（2026-09-07 に 1 石から集合へ、[features.md](features.md) §3）: 石を選ぶと、その集合で絞った
  内側の年表 — 「集合そのもの」＋「集合 × 共起する石」の行が**自動で**並ぶ（この案件で何を使っていたかの発見）。§6 のグラフで
  石を足すほど内訳が深くなり（`XX案件` → `XX案件 × Vue.js` の内訳 → …）、外せば戻る。行の石のチップはその 1 石に置き換え。
  行にタグをチップで足すと 3 タグ以上に ad-hoc で深掘りできる（保存しない。保存したくなったら後続機能）。
  投稿一覧へは「投稿一覧へ」で辿れる — 選んだ石は共有なので、着いた先は既に同じ集合で絞られている。
  wire は `GET /api/stats/timeline?focus=<id>[,<id>…]`（1 石は #30 以来の形のまま、✅ 集合は 2026-09-07 #52）。
- 棒の上に件数や密度（期間 ÷ 件数）を添えると「細く長く」と「太く短く」が見分けられる。
  **2026-09-09 から注記は「量 N · 厚み x%」**（[ADR-0007](adr/0007-spanning-post-amount-is-days-times-thickness.md)、✅ 2026-09-12）:
  量 ＝ 行の苔片の量の和（wire の `amount`。枚数 `count` は残り、棒の title「N 片 · 活動 x/y か月」と空の AND 行の「0 片」が読む）、
  厚み ＝ 量 ÷ 期間の日数（`Math.round` の %）。続く苔片が自分で言う厚みと同じ語で石の厚みを読む。1 日に何片も積めば 100% を超え、そのまま出す。
- 単棒は歯抜け期間をぶっ通しに見せる（React を 2019 と 2023〜 で使うと 1 本に見える）ので、
  **月セグメント棒**で活動月だけを塗る（✅ 2026-09-05）: 各行が活動月ごとの件数（`months`、疎・昇順）を持ち、
  棒は「最初の日〜最後の日」を薄い下地にして活動月を実線で重ねる（休眠した月は下地だけが残る。
  両端の月は最初の日・最後の日で切るので、棒が苔片より外へ伸びない）。「月」バケットは `first_day` / `last_day` を
  コアの純粋関数（`amountByMonth` / `enumerateMonths`）で範囲展開する — SQL は日の 2 列と厚みを生で取るだけで、読み時の TZ 変換は無い
  （日は書く側でしか切らない。SQLite の `date()` / `strftime()` は UTC 基準なので SQL では切らない）。
  軸が `first_day` / `last_day` になったので（2026-09-06、[ADR-0005](adr/0005-post-axis-is-day-range.md)、✅ merge #43）、続く苔片は
  触れる各月に 1 だった —— 2026-09-12 からは（ADR-0007）**`months` は各月の量** `{ month, amount }`（その月に重なる日数 × 厚み、
  単日は 1。core の `amountByMonth`）で、月は日を分割するので **和は行の `amount` に等しい**。セグメントのツールチップは「YYYY-MM · 量 N」。
  月ごとの濃淡は付けない（量は棒の上の注記で読む）。
- 軸ラベル（1 月は「YYYY年」、他は「M月」。右端は「今日」）は**軸の px 幅**から本数を決める（✅ 2026-09-05）:
  月境界を候補にし、「今日」に食い込むラベルは退き、暦に揃った刻み（1・3・6 か月 → 1・2・5・10・20・50 年）を
  隣と重ならなくなるまで粗くする。幅は ResizeObserver で測る — 本数だけで間引くと 390px の多年軸で年が重なり、
  1000px でも最後の年が「今日」に重なった（#38 で観測）。
- 投稿一覧（新着順リスト。2026-09-07 から別の見かた `/年表` に対して `/`）とは別物 — こちらはタグの年表。画面では「年表」と「投稿一覧」で、
  「タイムライン」の語は使わない（[CONTEXT.md](../CONTEXT.md)）。
- 集計は `post_tags ⋈ post` の `MIN(first_day)` / `MAX(last_day)` + 件数だけ（ADR-0005、✅ 2026-09-06 merge #43。`created_at` は読まない）。組み合わせ行も
  `tag_id IN (…)` ＋ post ごと `HAVING COUNT(DISTINCT tag_id) = n` の SQL 1 発
  （[data-model.md](data-model.md) の集計節）。本文不要＝暗号化と両立。

## 実装方針

- 重いダッシュボードライブラリは入れず、まずは **自作 SVG + 軽量ヘルパ**。
  - ヒートマップ・累積グラフは SVG の矩形/パスで十分組める。
  - 必要になったら `visx` や `Observable Plot` など関数志向で軽いものを検討。
- 集計はサーバ側（タグ×日の集計クエリ）でやり、フロントは描画に専念。
  - 本文は暗号化されるが、**日時・タグはメタデータとして平文**なので集計可能（[ADR-0001](adr/0001-body-encrypted-at-app-layer.md)）。
- カラーパレットは苔をテーマに（深緑〜黄緑〜枯れ茶のグラデーション）。ダークモード対応。
