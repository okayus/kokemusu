# タブ 2 つと「選んだ石」— 実装計画

決定は 2026-09-07 の論点 5 つ（下の「決めたこと」）。根拠は [features.md](../features.md) §3、[visualization.md](../visualization.md) §6 / §8。
**UI が本番稼働したらこのファイルは削除**（結論は features / visualization / CONTEXT.md と log に残る）。

## 決めたこと（論点 5 つ）

1. **年表タブで橋（エッジ）をタップ → 軸を 2 石に**。年表の軸は「石 1 つ」から「石の集合」へ広がる（§8 の行の一般形「タグ集合が全部付いた苔片」の延長）。
2. **投稿一覧タブで石（ノード）をタップ → 絞り込みに足し引き**（もう一度で外れる）。橋は両端をまとめて足し引き。
3. **年表タブでも石は足し引き**。軸 ＝ 選んだ石の集合。空なら「すべての石」。
4. **選んだ石は両タブで共有**（状態は 1 つ）。投稿一覧の絞り込みと年表の軸は常に同じ集合。年表の「投稿一覧へ」はタブを移るだけ。
5. **タブの名前は「投稿一覧」と「年表」**（どちらも今の見出し。「タイムライン」は年表と紛れるので画面から外す）。

## 形

- **タブ**は sticky なバーの直下。長い投稿一覧のどこからでも切り替えられる。**両方を載せたまま隠す**（読み込んだ苔片・絞り込み・軸が消えない）。
  URL に載せる: 投稿一覧 ＝ `/`（既定）、年表 ＝ `/年表`（SPA fallback: `not_found_handling` ＋ `app.notFound → ASSETS.fetch` で index.html が返る）。
  `<a>` を SPA 側で受けて `pushState`、`popstate` で戻る。絞り込み・軸・期間は今までどおり URL に載せない。
- **投稿一覧タブ**: 苔（総草）→ 石のつながり → 投稿一覧。伸びる節は最後（features §3 の原則）。グラフは畳まない（見出しまで 34rem 幅で 740px ほど。畳みたくなったら `<details>`）。
- **年表タブ**: 石のつながり → 年表。総草は出さない。
- **状態**（`Garden`）: `stones: TagSummary[]`（選んだ石。共有）／ `period`（投稿一覧だけ）／ グラフの期間 今月・今年・全期間（共有。投稿一覧の期間とは連動しない）／ view（URL）。
- **グラフは操作盤**: 選ばれている石は `aria-pressed="true"` ＋ 強調、両端が選ばれている橋も強調。タップ後の移動（scrollIntoView）は結果が見えていないときだけ（`block: "nearest"`）— 続けて押せるようにグラフを画面から追い出さない。

## 操作の対応表

| 操作 | 投稿一覧タブ | 年表タブ |
| --- | --- | --- |
| 石（ノード） | 選んだ石に足し引き → 絞り込み（AND） | 同じ → 軸 |
| 橋（エッジ） | 両端をまとめて足し引き（両方あれば外す、なければ両方足す） | 同じ |
| 総草のマス | その日に絞る（石はそのまま。今と同じ） | 総草が無い |
| 苔片のチップ | 選んだ石を**その 1 石に置き換え**（見に行く導線。今と同じ） | 出ない |
| 年表の行のチップ | 出ない | その 1 石に置き換え（今の focusOn） |
| 絞り込みチップ「A ×」 | その石を外す（軸も動く ＝ 共有の帰結） | 出ない |
| 「解除」 | 石も期間も空に | 出ない |
| 年表の「投稿一覧へ」 | 出ない | 投稿一覧タブへ移る（絞り込みは既に同じ集合） |
| 年表の「すべての石へ」 | 出ない | 選んだ石を空に（投稿一覧の絞り込みも外れる） |
| 行の ＋（深掘り） | 出ない | 今のまま ad-hoc の行（選んだ石には触れない） |

## 受領（積んだあと）

- 投稿一覧タブ: 今のまま（いま積んだ → 先頭へ移動＋「積みました」／ 絞り込みの外 → 「積みました（いまの絞り込みの外）」／ 過去・続く苔片 → 「YYYY/MM/DD に絞る」）。
- 年表タブ: **タブは動かさない**。「積みました」＋ ボタン「投稿一覧へ」（いま積んだ苔片は投稿一覧タブへ移って先頭へ。過去・続く苔片は「YYYY/MM/DD に絞る」がタブを移って絞る）。年表の棒が伸びるのは見える（`mossVersion`）。
- 空状態: 苔片が無い年表タブは節を消さず「まだ石がありません」系の文（今は `return null`）。グラフは今のまま育つまで出さない。

## API（PR 1）

- `GET /api/stats/timeline?focus=<id>[,<id>…]` — focus を **id の列**に（1 つは今のまま有効。`parseTagsParam` と同じ綴りだが 1 個から）。
  行 ＝ 「集合そのもの」1 行 ＋ 「集合 × 共起する石」（集合を全部持つ苔片の中で共起する各石）。集合の並びはリクエスト順（`tags=` の `tagsInOrder` と同じ）。
  SQL は `tags=` の `HAVING COUNT(DISTINCT tag_id) = n` で集合の苔片を引き、その苔片に付く他の石で group（`focus` の自己結合を集合に一般化）。
  `focus` と `tags` は今までどおり排他。`stats.test.ts` に 2 石・3 石・未知 id・共起なし の表テスト。

## 手順（PR 2 本。どちらも migration なし ＝ auto-merge 可）

1. **PR 1 `claude/timeline-focus-set`**: API だけ。UI は 1 石の focus のまま通る（振る舞い不変）。単体 `pnpm test`、型 `pnpm check`。
2. **PR 2 `claude/tabs`**: `modern-web-guidance` を **nav / tabs / hidden / pushState** で読んでから。
   1. `useView()`（URL ↔ view、`<nav>` ＋ `aria-current="page"`）とバー直下のタブ。両パネルは `hidden`。`.shell > section` の scroll-margin はそのまま。
   2. `Garden`: `postFilter` ＋ `timelineFocus` を `stones` 1 本に。`showPosts([t])`（置き換え）と `toggleStone` / `togglePair`（足し引き）。`TagTimelineSection` は `focus: TagSummary[]`。
   3. `TagGraphSection` を 1 つの状態で両タブに描く（`selected` を受けて `aria-pressed` ＋ CSS）。
   4. 受領の分岐（年表タブ → 「投稿一覧へ」）、年表の空状態、年表の head「A × B」の内訳。
   5. docs（下）と e2e。使い捨て spec で ライト / ダーク / 390px、両タブ、選択の強調 を目視。

## DoD（e2e、golden path に足す手）

- タブ「年表」へ → グラフの石をタップ → 「「苔」の内訳」／ もう 1 石をタップ → 「「苔 × e2e」の内訳」と `A × B` の行 ／ 同じ石をもう一度 → 外れる。
- タブ「投稿一覧」へ → 絞り込みチップが同じ 2 石（共有）→ チップの × で 1 石に → 年表タブの軸も 1 石。
- 投稿一覧タブで橋をタップ → 2 石が足される（今の導線 3 の置き換え版）。
- `/年表` を直接開いて年表タブが出る。再読み込みで残る。
- 既存: 導線 2「投稿一覧へ」はタブ移動に、グラフの石タップ→内訳 は年表タブで。
