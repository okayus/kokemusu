# 機能仕様

可視化は核心なので別ファイル [visualization.md](visualization.md) に切り出す。ここでは投稿・タグ・閲覧・API の機能をまとめる。

## 1. 投稿（苔片）

ツイート感覚 ＝ **摩擦をゼロに近づける** のが最優先。

- 短文テキスト中心。1日に何回でも投稿できる。
- **Markdown 対応**（コードブロック・リンク・リスト程度。重い装飾はいらない）。見出し・箇条書き・
  番号つき・チェックリスト・引用・コード・表・水平線・強調まで。コンポーザと編集フォームには
  同じ描画器を通す `<details>` のプレビューがある。
  - `typescript` タグでコードスニペットを貼れることは地味に重要。
  - 生 HTML は解釈せず字として出る。画像は `<img>` ではなくリンクになる（[ADR-0004](adr/0004-markdown-renders-to-react-elements.md)）。
- 投稿時にタグを複数付与できる（[タグ](#2-タグ)参照）。
- **見出し（`title`）は任意**。付けなくても投稿できる（摩擦ゼロを守る）。フォームは本文 1 欄のままで、トグルで見出し欄を出す
  （✅ 2026-09-05、ダイアログの `<details>`「見出しを付ける」。畳んだまま見出しが残っていれば summary にその見出しが出る）。
  手動でも API でも付けられる。タイムラインは見出しのある苔片だけ本文の上に小さく表示。検索は見出しも対象。暗号化は本文と同じ（ADR-0001）。
- タイムスタンプは自動記録（投稿した瞬間・更新日時）。積み上がる「日」はそれとは別（次項）。
- **過去の日に積める・続けて積める**（2026-09-06 決定、[ADR-0005](adr/0005-post-axis-is-day-range.md)。未実装 —
  [plans/day-axis-and-kind.md](plans/day-axis-and-kind.md) の A2）: ダイアログの `<details>`「日を選ぶ」に「いつ」「〜いつまで」の
  ネイティブ date 2 欄（閉じたまま ＝ 今日。畳んでも選んだ日が summary に出る）。1 日だけなら過去のその日に、範囲なら
  **続く苔片**（[CONTEXT.md](../CONTEXT.md)）として最初の日〜最後の日に積まれる。縛りは `最初の日 ≤ 最後の日 ≤ 今日`
  （`max` は投稿一覧の応答の `today`、逆転は期間絞り込みと同じくブラウザの検証で止める）。未来には積めず、まだ続くものは
  今日を最後の日にして積み、後で編集して伸ばす。カードは いま積んだ苔片だけ時刻を出し、過去に積んだ苔片は
  「2025/03/01」「2025/03/01 〜 2026/01/31」に小さく「2026/09/06 に積む」を添える。向きも日も下書きに退避する。
- **向き**（インプット／アウトプット／両方、[CONTEXT.md](../CONTEXT.md)。同 B）: 本文の下の 3 択チップ（radio）を常に出し、
  押さなければ未分類（摩擦を増やさない）。タグではなく苔片の列で、総草の色相を決める（[visualization.md](visualization.md) §1）。
  同じ石に積む はタグだけを引き継ぎ、向きは引き継がない。`?kind=` の絞り込みは要るときに additive で足す。
- 投稿後の **編集・削除**（削除は物理削除 + 確認ダイアログ。誤削除の受け皿はエクスポート /
  D1 Time Travel / 定期バックアップの層で持つ — [ADR-0003](adr/0003-post-delete-is-physical.md)）。
- 下書き機能は **あえて作らない**（書いたら即投稿、というツイート感を守る）。
  - ただし投稿失敗時のローカル退避（送信前テキストの保持）はする。ダイアログを閉じたときも同じ退避が効く。
- **投稿フォームはダイアログ**（✅ 2026-09-05）: トップに常設せず、ヘッダー（sticky）の「積む」か `n` で開くネイティブ `<dialog>`。
  見出し欄は `<details>`「見出しを付ける」で出す（決めること 7 の「トグル」）。成功したら閉じて本文もタグも空にし、
  新しい苔片へ連れていく（投稿一覧の先頭へ。絞り込みの外に落ちたら動かず「積みました（いまの絞り込みの外）」と告げ、
  苔が濃くなるのが受領。過去に積んだ苔片は先頭に来ないので、同じ告知に**その日（範囲）に絞るボタン**を添える ——
  勝手には絞り込まない。A2）。Esc・背景タップ・戻るジェスチャで閉じても下書きは残り、次に開くと戻る（閉じる ＝ 保存、破棄ではない）。
- **同じ石に積む**（[CONTEXT.md](../CONTEXT.md)、✅ 2026-09-05）: 投稿一覧の各苔片に付くボタン。押すとその苔片の
  タグだけを引き継いでダイアログが開く（書きかけの本文は保ち、タグ欄を置き換える）。タグの無い苔片には出ない。
  タグの引き継ぎはこの明示操作だけ —— 投稿後にタグを残す暗黙の持ち越しはしない（消し忘れで違う石に苔が付くのを防ぐ）。
- **キーボードショートカット**: `n` で「積む」ダイアログを開く（入力欄にいる間・ダイアログが開いている間は効かない）、
  `Cmd/Ctrl+Enter` で投稿。
- 画像・ファイル添付は将来フェーズ（[roadmap](roadmap.md)）。MVP はテキストのみ。
- UI 以外からの投稿は [§7 API 自動投稿](#7-api-自動投稿pat)。

## 2. タグ

タグは「苔が生す石」＝振り返りの軸。

- 1投稿に **複数タグ** を付与できる（多対多）。
- 入力は自由記述 ＋ **既存タグの補完**（タイプして候補から選ぶ）。
  - 表記ゆれ防止のため、補完を強めに効かせる。
- タグ単位のメタ情報:
  - 色（苔の色味。可視化に使う）
  - 絵文字 / アイコン（任意）
  - 説明（任意。「このタグで何を記録しているか」のメモ）
- **タグ運用機能**（後から育てる前提）:
  - リネーム
  - 統合（マージ：`TS` と `typescript` を1つに）
  - 別名（エイリアス）
  - アーカイブ（使わなくなったタグを一覧から隠す）
- 構造は **フラット**（階層なし）から始める。必要なら後で親子関係を検討。
- **案件（プロジェクト）もタグで表す**（2026-09-03。[CONTEXT.md](../CONTEXT.md) タグ/見出しの項）:
  「どの案件で・どの技術を・いつ」は共起として §6/§8 に乗る。運用は 2 つ —
  (1) 仕事の苔片には案件タグを 1 つ付ける習慣（[visualization.md](visualization.md) §8 フォーカス年表の母集合になる）、
  (2) 案件タグの名前・説明に顧客の固有名詞を書かない（平文メタデータ — [security.md](security.md)）。
  案件タグと他のタグの区別列は持たない（色・絵文字で目印。「仕事だけビュー」が要るときに NULLABLE の `kind` を後付け）。
- タグ同士の**関係**（同じ投稿に一緒に付く＝共起）は階層ではなくグラフとして見せる → **タグ関係グラフ**（[visualization.md](visualization.md) §6）。常に一緒に付く 2 タグは統合候補、という運用のヒントにもなる。

## 3. タイムライン / 閲覧

- **トップの構成**（✅ 2026-09-05）: 上から 苔（総草）→ 年表 → 石のつながり → 投稿一覧。書く面はダイアログ（§1）に退き、
  トップは振り返りに使う。投稿一覧は「もっと遡る」で伸びる唯一の節なので最後に置き、可視化の位置が動かない。
  各苔片の操作は「同じ石に積む／編集／削除」の順（頻度順、破壊的なものを端に）。
- 時系列フィード（積み上がる「日」の新しい順、同じ日の中は書いた順。続く苔片は最初の日の位置 —— 年表の開始日順と同じ向き。
  ADR-0005）。無限スクロール or ページング。
- 絞り込み:
  - タグ（複数選択：AND / OR）
  - 期間（日・週・月・年、カスタム範囲）— ✅ 2026-09-05。API は `?from=`/`?to=`（JST の日、両端含む、片側だけでも可。
    総草の窓と同じ wire 形）の 1 つで、日・週・月・年はその上のプリセット。UI は投稿一覧の「期間で絞る」
    （今日 / 今週 / 今月 / 今年 ＋ ネイティブ `<input type="date">` 2 欄。逆転はブラウザの検証で止まる）。タグとは AND。
    期間は**重なり**で引く（続く苔片は在った日のどれにも出る。ADR-0005）。
- **全文検索**（本文・見出し・タグ）。本文と見出しは暗号化されているので D1 の FTS は使わず、期間で絞って復号して走査する（[ADR-0001](adr/0001-body-encrypted-at-app-layer.md)）。重くなったら端末内索引。
- 「日」単位ビュー（その日の投稿をまとめて振り返る）— ✅ 2026-09-05。専用画面ではなく期間絞り込みの 1 日形:
  総草のマスをタップ（[visualization.md](visualization.md) §1）するか「今日」プリセットで、投稿一覧がその日に絞られる。
- パーマリンク（個別投稿への直接リンク。自分用ブックマーク）。

## 4. 振り返り・サマリー

- 週次 / 月次 / 年次の振り返りビュー（投稿数、タグ内訳、ハイライト）。
- 「今日は何の日」的な過去回顧（On this day：1年前の今日の投稿）。
- タグごとの累積・継続状況、タグ関係グラフ（→ [visualization.md](visualization.md)）。

## 5. データ管理

- **エクスポート**: 全データを JSON / Markdown で書き出し（バックアップ・移行用）。
- **インポート**: エクスポートしたデータの取り込み。
- 定期バックアップの手順（セルフホスト前提なので運用ドキュメント込み）。
- 暗号化バックアップ（→ [security.md](security.md)）。

## 6. 設定

- 認証・セキュリティ設定（パスキーの登録 / 端末一覧 / 削除、セッション管理）。
- **API トークン管理**（発行・一覧・失効。[§7](#7-api-自動投稿pat)）。
- 表示設定（テーマ：ライト/ダーク、苔の配色、タイムゾーン、週の開始曜日）。
- タグ管理画面（一括リネーム・統合・色設定）。

## 7. API 自動投稿（PAT）

✅ **実装済み（2026-09-03）** — 以下の設計のとおり。`PAT_PEPPER` は fail closed（未設定 = 発行 503・検証は全不一致）なので、
本番で使い始める前に `wrangler secret put PAT_PEPPER` が必要（[data-model.md](data-model.md) `api_token`）。

人間が UI から書くのと同じ「苔片」を、**別アプリ・CLI・エージェントが自分として投稿できる**入口。
最初の送り側は **mazuoboeru**（クイズアプリ）の「今日の結果」日次投稿。
設計は `cloudflare-workers-pat-bearer-auth`（mazuoboeru で本番稼働中の発行側パターンを、苔むすが**受け側**として使う）。

- 認証は **PAT（personal access token、Bearer）**: 苔むすの設定画面で発行 → 送り側が保持 → `Authorization: Bearer kokemusu_pat_…`。
  苔むすは **送り側が誰かを知らない**（分かるのは「どのユーザ・どのスコープ」だけ）。
- ルート: `POST /api/posts`（スコープ `post:write`）。body は UI の投稿と同じ形（`body`・`tags`・任意の `title`。2026-09-06 からは任意の
  `firstDay` / `lastDay` / `kind` も —— 送り側は「昨日の分」を昨日に積め、向きを付けられる。受け側は検証するだけ）。送り側固有のフィールドは持たない。
  スモークテスト用に `GET /api/auth/me` も PAT で読める（whoami。返るのは id と表示名だけ）。**それ以外の route に PAT は届かない**
  （タイムライン閲覧・stats・tags は `403 session_required` —— post:write のトークンが漏れても日記は読めない）。
- セッション（Cookie）でも PAT でも同じ route が通る。認証ミドルウェアは PAT を Cookie より先に判定し、Bearer 付きリクエストは CSRF の Origin チェックを免除（Cookie という ambient credential が無いので偽造できない）。
- 送り側がリトライするなら `Idempotency-Key` ヘッダを 24 時間記憶して二重投稿を防ぐ（受け側の責務。必要になってから）。
- トークン管理（設定画面・**セッション必須**＝PAT で PAT は作れない）: 名前を付けて発行 → **一度だけ表示** → 一覧（名前 / 作成 / 最終使用 / 状態）→ 失効（行は残す）。1 本の失効はセッションにも他の token にも影響しない。
- 保存は `sha256(token + PAT_PEPPER)` のみ（[data-model.md](data-model.md) `api_token`）。D1 が漏れても生きた credential にならない。
- PAT で届く mutation は bot スキャン対策の対象（ログイン用とは別のレート制限。接頭辞チェックで junk は D1 に触れる前に弾く）。ログに `Authorization` ヘッダや token を出さない（`id` だけ）。
- ✅ **mazuoboeru 側は (i) 自分専用**（mazuoboeru の Worker Secret に苔むすの PAT を 1 本置き、Cron が日次で push。2026-08-23）。受け側（苔むす）は送り側を知らない汎用設計（[ADR-0002](adr/0002-api-posting-via-receiver-side-pat.md)）なので、mazuoboeru が per-user (ii) に広がっても苔むすは無変更。

## 機能の優先度

| 優先度 | 機能 |
| --- | --- |
| **MVP 必須** | 投稿 CRUD、タグ付与・補完、タイムライン、タグ絞り込み、パスキー認証、ヒートマップ1種 |
| 高 | API 自動投稿（PAT）、全文検索、累積グラフ、タグ運用（リネーム/統合）、エクスポート |
| 中 | 振り返りサマリー、タグ関係グラフ、苔の庭ビュー、ストリーク、ダーク/配色設定 |
| 低 | 画像添付、PWA/オフライン、On this day、インポート |

詳細な段階分けは [roadmap.md](roadmap.md) を参照。
