# 続く苔片は厚みを持ち、量 ＝ 日数 × 厚み —— 「単日 | 続く(厚み)」の直和を型・CHECK・解釈・テストで同じ形に表し、ADR-0005 の「在った 1 片」を量については置き換える

2022-04〜2024-03 の案件を 1 枚の続く苔片で積むと、[ADR-0005](0005-post-axis-is-day-range.md) の「在った 1 片」では石も年表の件数も
1 片で、2 年の打ち込みが日次のメモ 1 枚と同じ大きさにしかならない。持ち主の望みは「2 年 × 6 割（月 20 営業日）分を
積んだことにする」。**続く苔片は「厚み」（期間のうち打ち込んでいた日の割合、1〜100 の整数 %）を必ず持ち、量 ＝ 暦日数 × 厚み。
単日の苔片は量 1 で厚みを持たない（1 枚 ＝ 1 日 × 100%。基準は「100% ＝ 毎日 1 枚」）。苔片が積み上がる日々は
`単日(日) | 続く(最初の日, 最後の日, 厚み)` の直和であり、これを core の型・DB の CHECK・wire の解釈・テストの法則の 4 箇所で
同じ形に表す。「在ったのに量 1」の続く苔片（sheet）は持たず、期間についての振り返りは書いた日の単日で書く。**
既存データは壊してよい（持ち主の判断）ので、`post` を再構築して既存の続く苔片には 100% を入れ、あとで画面で直す。
用語は [CONTEXT.md](../../CONTEXT.md) の「厚み」「量」。

## 意味の置き場（コードが意味を表す、が設計の要件）

- **core**: `Stacking = { on: "day", day } | { on: "days", firstDay, lastDay, thickness }`（`firstDay < lastDay`）。`Thickness` は
  1〜100 の整数の branded 型で、作れるのは 1 つの constructor（zod の schema）だけ。量は `amountOf(stacking, window?)` の純粋関数で、
  保存しない。年表の測った厚み（量 ÷ 日数、小数で 1 を超えうる）は宣言の `Thickness` とは別の型。
- **DB**: `thickness integer` ＋ CHECK 3 つ —— `first_day <= last_day`、`(first_day = last_day) = (thickness IS NULL)`、
  `thickness IS NULL OR thickness BETWEEN 1 AND 100`。NULL は「単日」と 1 対 1 で、意味を背負う sentinel ではない。
- **境界**: wire → core は `parseStacking(body, today): Stacking | null`（検証して通すのではなく解釈して型にする。null → 400）、
  DB → core は `decodeStacking(row)`（CHECK が守るはずの形が崩れていれば throw —— `requireSpan` と同じ流儀）、core → DB / wire は
  `encodeStacking`（NULL が生まれる唯一の場所）。総草・年表の既存関数には `daySpanOf(stacking)` で日々だけを渡す ——
  総草が量を読まないことが引数の型に出る。
- **テスト**: 法則で書く。単日 ＝ 1 ／ n 日 × 100% ＝ 単日 × n ／ 窓いっぱい ＝ クリップ無し、重ならなければ 0 ／ months の和 ≧ 量 ／
  単日 ＋ 厚み・範囲 − 厚み は parse で null ／ decode は壊れた行で throw ／ encode ∘ decode ＝ id。

## Considered options

- **「在ったのに量 1」の続く苔片（sheet）を残す**（最初の案。NULL ＝ sheet、core は `sheet | thick` の直和）: 既存の続く苔片を
  動かさずに済むが、年を跨ぐ振り返りが総草を 365 日光らせながら量 1 という中間の状態を持ち、型は 3 変種、DB の NULL は
  「単日」と「sheet」の 2 つの意味を背負う。既存データを壊してよいと決めた時点で残す理由が消えた。振り返りは書いた日の単日。
- **既定 100%（範囲だけの要求を黙って毎日で積む）**: 意味を黙って補うので [ADR-0006](0006-no-post-title.md) の `strictObject` と
  姿勢が割れる。範囲には厚みが必須で、無ければ 400。
- **営業日の暦（平日だけ数える）**: 「どの日か」が決まるので総草と相性は良いが、祝日・休暇・週 1 の副業を表せない。
  % は粗いが汎用で、範囲を伸ばせば量が追随する。月あたり日数・週あたり日数・量そのものを書く形は、% への換算を UI の
  目盛りと換算表示で吸収する。
- **総草も量を読む**: 固定 5 段階（`level = min(count, 4)`）で各日 +0.6 は、切り上げなら今の +1 と同じ、切り捨て・四捨五入なら
  40% の案件が一度も光らない。総草は「在ったこと」を見せる場所として据え置く。
- **期間をクリップしない**: SQL の `COUNT` を `SUM` に変えるだけで済むが、今日まで続く案件が「今月」の石に 2 年分で乗る。
  日と厚みを取って core で足す。
- **列を足すだけ（NULLABLE、不変条件はコードとテストだけ）**: 再構築の手間と罠が無いが、DB が「単日に厚み」を抱えられ、
  NULL の意味はコードの外に出ない。再構築は 0004 の recipe があり、データは壊してよいので CHECK で刻む。
- **NOT NULL DEFAULT 100（単日も 100 を持つ）**: 式は一様になるが、単日の 100 は入力ではなく定数で、単日 60 ＝ 量 0.6 が
  表現できてしまう。結局 CHECK が要る。
- **PATCH は向きと同じ全送り（省略 ＝ 外す）**: `lastDay` だけ書いて伸ばす PATCH で厚みが消える。日に付随する属性なので
  日と同じ据え置き。
- **量を列に保存する**: 日を伸ばすたびに書き直しになる。読むときに出す。

## Consequences

- **`post` の 2 度目の再構築（`0006`）**: 0004 と同じ recipe（`post_tags_keep` に退避 → `__new_post` に CHECK 付きで作り
  backfill → `DROP TABLE post` / RENAME / index → `INSERT OR IGNORE` で復元 → 退避を落とす。PRAGMA は書かない）。backfill は
  `first_day < last_day` の行に 100、単日は NULL。`migrations.test.ts` の免除リストに 2 本目として載せ、文の並びを固定。
  リハーサルは `.wrangler/e2e` の写しで、本番は `cloudflare-d1-drizzle-migration` の runbook（merge 前に export、事後に
  `post` / `post_tags` の COUNT 一致）。
- CHECK の式を将来変えるときはまた再構築。この不変条件は変わらない見込みで、そのために刻む。
- **wire**: `POST` / `PATCH /api/posts` の body に `thickness?: number | null`。単日に数 → 400、範囲に無し / null → 400
  （範囲には厚みが必須）。PATCH は省略 ＝ 据え置き、null ＝ 無し（単日に縮める要求と一緒のときだけ正）、数 ＝ 付け替え。
  結果を `parseStacking` に通して null なら 400 —— 単日に縮めて厚みが残る・単日を伸ばして厚みを言わない はここで落ちる。
  PAT も同じ。応答の苔片は `thickness: number | null`（null ⇔ 単日、CHECK と同じ形）。
- **集計**: 石のつながりのノードと橋は枚数から量の和へ（期間はクリップ、core で足す。wire は `count` → `amount`、小数）。
  年表の行は枚数に加えて量を持ち、注記は「量 N · 厚み x%」（厚み ＝ 量 ÷ 期間の日数。1 日に何片も積めば 100% を超え、
  そのまま出す）、活動月は各月 その月に重なる日数 × 厚み（和は量以上）。総草・「計 N 片」・吸う／出す の分母は枚数のまま。
  累積グラフ（未実装）は日ごとに厚みずつ積む。量は小数のまま足し、丸めるのは表示だけ（731 × 60% ＝ 438.6 → 439）。
- 石の目盛り（`nodeRadius` は約 46 で上限）は量で早く飽和する。目盛りの見直しは実装時の判断。
- **UI**: 積む日の欄で「いつ」と「〜いつまで」が違う日になったときだけ「厚み」のスライダー（1〜100、初期値 100、
  目盛り 14 / 60 / 71 / 100）と換算「60% · 731 日のうち 439 日分」が現れ、範囲なら必ず送る。単日に戻せば消えて null を送る。
  カードと編集フォームの summary に「厚み 60%」。下書きに退避。
- **既存データ**: 続く苔片は全部 100%（毎日）になる。長い振り返りの 1 枚があれば merge 後に画面で直す（単日に戻す、または
  厚みを下げる）。
- ADR-0005 の「続く苔片は在った 1 片」は、総草の「在った各日 +1」を残して、量については置き換える。用語集の「続く苔片」
  「厚み」「量」を改訂。
