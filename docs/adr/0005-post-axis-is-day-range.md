# 苔片が積み上がる軸は「日」の範囲（`first_day` / `last_day`）であり、`created_at` ではない

苔片は**過去の日にも積め、最初の日から最後の日まで続く 1 片としても積める**（過去の学びを後から書く、
2025-03〜2026-01 の案件を 1 枚で書く）。これまでは `created_at`（書いた瞬間）を軸と同一視し、総草の窓・
年表の MIN/MAX と活動月・石のつながりの期間・一覧の並びとカーソルと期間絞り込み・index の 6 箇所が
それを読んでいた。**`post` に `first_day` / `last_day`（日本時間の `YYYY-MM-DD`、両方 NOT NULL、単日は
同値）を持ち、可視化・絞り込み・並び順はすべてこれを軸にする。`created_at` は他のテーブルと同じ
「行を作った（投稿した）瞬間」に戻る。** 続く苔片は「その日々ずっと在った 1 片」として数える
（[CONTEXT.md](../../CONTEXT.md)）。データがまだ少ない時期に `post` を 1 回再構築して入れる。

## Considered options

- **`created_at` を過去の値で書く（列はそのまま）**: 最小の diff だが、列名が嘘になる（「作った」時刻でない
  ものが入る）上に、過去の苔片に `00:00` という作り物の時刻が要る。
- **`created_at` は書いた瞬間のまま、軸の上書き列（NULLABLE）を足す**: 読む側 6 箇所すべてに
  `COALESCE(上書き, created_at)` を書く。1 箇所忘れると「過去に積んだのに今日に光る」——
  [ADR-0003](0003-post-delete-is-physical.md) が嫌った `isNull(deleted_at)` の忘れと同じクラスで、
  単体テストは D1 なしなので気づけない。
- **時刻の軸を改名する（`stacked_at` ＋ `stacked_until`）**: 名前は直るが、軸が「瞬間」のままなので
  過去の苔片の時刻は作り物のまま。「積まれた瞬間」という概念は用語集に無い。
- **「日」を列にする（採用）**: 用語集の「日」（苔片が積み上がる単位）がそのまま列になり、続く苔片は
  `first_day < last_day` というだけ。時刻は `created_at` にだけ残り、それは本当に書いた時刻なので
  §5 の時間帯分布の出どころとしても正しい。読み時の TZ 変換（`dayKey` / `dayStartMs`）が消え、
  SQLite の `date()` / `strftime()` を避ける理由もなくなる（使う必要がなくなる）。
- **続く苔片の数え方**: 「毎日 1 片の代役」（年表の件数と石の大きさが日数分膨らむ —— 1 回の振り返り投稿が
  数年分の日次より大きい石になる）と「年表にだけ効く」（総草のマスは 0 件なのにタップすると出る、
  単日は光るのに 2 日の続きは光らない）を退け、「在った 1 片」（総草は各日 +1、件数は +1）にした。

## Consequences

- **`post` の再構築が 1 回要る**（NOT NULL 列の追加）。D1 は `PRAGMA foreign_keys=OFF` を無視するので
  `DROP TABLE post` で `post_tags` が cascade で消える —— migration の中で `post_tags` を退避して復元し、
  `cloudflare-d1-drizzle-migration` の runbook（事前バックアップ・事後の行数確認）を踏む。
  既存行の backfill は `created_at` を日本時間で日に切る 1 回限りの SQL（Tokyo は DST が無い）。
- `dayKey` は**書く側だけ**が使う（いま積む = `dayKey(now)`、過去に積む = リクエストの日）。読む側は
  文字列比較: 総草の窓・期間絞り込み・§6 の期間は**重なり**で引く（`first_day <= to AND last_day >= from`）、
  年表は `MIN(first_day)` / `MAX(last_day)`、月は先頭 7 文字。
- 一覧の並びは `(first_day DESC, created_at DESC, id DESC)`（同じ日の中は書いた順）、カーソルは 3 要素。
  続く苔片は `first_day` の位置に出る（年表の開始日順と同じ向き）。
- 総草: 続く苔片は在った各日で +1（固定の 5 段階に乗る）。「計 N 片」はマスの合計ではなく
  **窓に重なる苔片の数**（絨毯で水増ししない）。
- 年表: 続く苔片は触れる各月で 1 —— `months` の和は `count` 以上になる（これまでは等しかった）。
  「N 片 · d日/片」は正直な数のまま。
- 縛り: `first_day ≤ last_day ≤ 今日`（サーバの日本時間）。未来には積めず、open-ended は作らない
  （続いているものは今日を最後の日にして積み、後で編集して伸ばす）。
- 過去に積んだ苔片には本当の時刻が無いので、画面が時刻を出すのは `first_day = last_day = dayKey(created_at)`
  の苔片（いま積んだもの）だけ。
- 単体テストと e2e の「`created_at` をずらして過去に置く」細工は、この機能そのもの（日を指定して積む）に置き換わる。
